================================================================================
USER JOURNEY - BEFORE vs AFTER
================================================================================

BEFORE (Developer-Oriented):
  1. App launches → Home screen
  2. Tap "+" → BLE Provision screen with technical state names
  3. See raw BLE connection states (CONNECTING_BLE, DISCOVERING_SERVICES)
  4. Manual WiFi scan button
  5. See provisioning logs with firmware status strings
  6. Raw success/error states

AFTER (Consumer-Friendly):
  1. App launches → Startup screen with animated intro
  2. Permission explanation screen (friendly descriptions)
  3. User taps "Continue" → Permission dialogs
  4. Home screen appears
  5. Tap "+" → Add Device screen (auto-scans)
  6. Tap device → WiFi Setup screen
  7. Select WiFi → Enter password → Tap "Connect Device"
  8. Provisioning Progress screen (friendly animations, no technical details)
  9. Success screen → "Go to Dashboard"
  10. Device appears on home screen

WHAT'S HIDDEN (Internal Only)
================================================================================

The following technical details remain internal and are NOT shown to users:
  • Provisioning state machine names
  • BLE connection debugging text
  • Firmware status strings
  • Raw RSSI signal values
  • Technical error codes
  • Provisioning logs
  • Service discovery details
  • Characteristic UUIDs
  • Base64 encoding/decoding details

These are preserved in console logs for debugging but never displayed in the UI.
